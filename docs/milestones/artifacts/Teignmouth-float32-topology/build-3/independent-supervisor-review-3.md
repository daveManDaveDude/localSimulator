Independently, S:615–639 writes its script-start record inside those still-absent leaves before `_selfcheck`/`_preflight_only` creates them at S:1386/1686. If a leaf were precreated to accommodate that write, the later existence checks at S:1384/1684 would reject it. Use one shared fixed path contract: parent handoff/start metadata must be available before the runner creates its absent leaf, or provide a single explicitly owned creation sequence. Do not bypass one-shot checks by precreating/removing evidence. Build-mode parent paths are consistent; this blocker affects both standalone modes.

3. **A refused repeat invocation can overwrite the previous caller record.** W:264–265 throws if the caller or another one-use path already exists, before exclusive creation at W:281. Nevertheless W's finally unconditionally calls `Save-Caller` at W:601. `Update-OwnedJson` replaces an existing destination at W:130–134. A repeat/refused invocation can therefore replace the prior caller record with this attempt's failure record despite never acquiring ownership. Track successful exclusive ownership and only update that owned file. The same guard is needed when path validation fails before a safe writable parent is established. Preserve previous invocation records unchanged.

4. **Pre-assignment failure can leave an uncontained suspended launcher alive.** W:422–437 creates the launcher suspended, captures native identity and updates the handoff before assigning it to the Job at W:438. If identity capture or the handoff update fails in that interval, W's catch only terminates the Job at W:553–568. The launcher is not yet in that Job; finally merely closes its thread/process handles at W:587–588, which does not terminate the process. Track assignment ownership and explicitly terminate/wait within remaining time for an unassigned suspended process before closing handles. Also W:492 closes `$scriptHandle` on a failed membership check without clearing it; finally W:589 closes it again. Keep single-owner cleanup. No base interpreter should be resumed unless containment succeeds, and no failed-launch process should be abandoned.

5. **Remaining clock/census paths do not consistently use the inherited absolute deadline.** W's descendant expansion at W:163–181 and native snapshot/job-list loops at W:321–323 have iteration bounds but no deadline checks; W:504–510 computes the next wait budget before `Assert-OwnedJobTree`, so a lengthy census can consume the budget and then the stale remaining wait is still used.
