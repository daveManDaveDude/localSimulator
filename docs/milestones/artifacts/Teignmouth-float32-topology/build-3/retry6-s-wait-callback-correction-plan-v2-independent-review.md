## Official API semantics

Verified against official publisher documentation during this review:

- Python's last-error-enabled foreign calls exchange the native error with a private thread-local copy. `ctypes.set_last_error` and `ctypes.get_last_error` write/read that copy; direct `ctypes.GetLastError` instead reads Windows' native value. The proposed private-copy sequence therefore matches the existing loader. [Python ctypes documentation](https://docs.python.org/3.13/library/ctypes.html#loading-shared-libraries), [get_last_error](https://docs.python.org/3.13/library/ctypes.html#ctypes.get_last_error), [set_last_error](https://docs.python.org/3.13/library/ctypes.html#ctypes.set_last_error).
- Process32NextW returns a Boolean and documents ERROR_NO_MORE_FILES for exhausted snapshot information. After a successful first row, this supports treating a false Next with the captured normal terminal code as enumeration completion. [Microsoft Process32NextW](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-process32nextw).
- ERROR_NO_MORE_FILES is 18. [Microsoft system error codes](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-).

Static S confirms `_api` uses `ctypes.WinDLL("kernel32", use_last_error=True)` at195, Process32NextW has HANDLE/PROCESSENTRY32W argument types and BOOL result at283–284, and no errcheck/replacement binding appears in the inspected source. The self-check uses that configured kernel. No new DLL, foreign function, import, prototype, right or loader mutation is required. Auditing/accessor failure is explicitly a blocker, not proof.
