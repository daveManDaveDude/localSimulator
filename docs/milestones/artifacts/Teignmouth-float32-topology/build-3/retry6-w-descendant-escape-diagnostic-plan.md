## Capture budget and cleanup priority

Preserve the original **10-second total QPC deadline**, all waits/termination/deadline handling and outer watchdog behavior. Optional capture starts only if at least **1000ms remain** on that same original deadline. Its check cutoff is `min(originalDeadlineQpc - ceil(1.0*frequency), firstFalseQpc + ceil(0.020*frequency))`: at most20ms of diagnostic opportunity with a one-second cleanup reserve. This is a subset of the original budget, not added runtime permission or a new mode deadline. If insufficient reserve, mark detail skipped and close immediately. Check before/after each optional native call and during each chain step; no sleeps, retries or later census. At most two extra native queries total per failing assertion, zero when skipped.

Optional storage/chain building must be stopped at the cutoff; closure cannot be skipped when expired. The original membership iteration/error construction remains unchanged and may still encounter its existing deadline rules. Pending diagnostic availability must never make it continue beyond the original deadline, change which error is primary, postpone required termination to write evidence, or convert an unknown to PASS. Serialization occurs only after catch cleanup, under remaining original time, and is skipped if time/clock is unavailable. No new file write is inserted; existing final caller persistence/fallback rules continue.

The reserve and post-call checks are not native-call preemption or a guarantee that cleanup completes in one second. Finite two-call/one-buffer/64-edge work is statically bounded; actual API/PowerShell/persistence latency and ten-second fit are unmeasured. Existing native calls have the same limitation. If coordinator/reviewer requires a guaranteed hard20ms interruption or guaranteed durable evidence before cleanup, STOP: that requires a different process/API boundary, not a larger allowance or misleading claim of safety.
