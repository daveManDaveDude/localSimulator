## Exact claim and trust assumptions

Trust the exact pinned CPython 3.13.7 interpreter/venv redirector, its bound standard-library/bootstrap files and the Windows loader to implement their documented installed behavior. Trust the reviewed frozen W/S/P and imported repository/package code to use only the enumerated profile locations and the known path changes below. Built-in/frozen interpreter modules have no separate disk file: their binding is the interpreter/runtime image. Disk-backed OS and extension modules are still file-bound; trusting the loader does not exempt arbitrary DLL files from binding.

This establishes that every on-disk executable/import/cache/archive candidate in the supported finite search profile was observed and matched to an existing frozen file binding before launch, with later census/preservation checks. It does not prove arbitrary trusted code is harmless or prevent it from violating the reviewed path contract, performing arbitrary native operations, or generating code in memory. Unmodelled path mutation/loading behavior discovered in review is unsupported and stops acceptance. Dynamic malicious behavior by trusted pinned code, a compromised OS, and concurrent file replacement between observation and load are outside this claim. Hash checks are not atomic load confinement. A later census mismatch is non-PASS detection, never proof that earlier unbound execution was prevented.
