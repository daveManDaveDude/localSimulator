# TVW-004 — Synthetic manifest and heightfield loader

**Status:** complete — independent Sol review `PASS`; coordinator gates and browser regression passed.

## Delivered

- A dependency-free v1 manifest validator accepts synthetic local worlds only. It checks required fields and literals, finite origins/extents, safe relative asset paths, 64-hex SHA-256, grid/extent consistency, safe sample arithmetic, and a 16-million-sample allocation cap.
- A Three.js-independent decoder reads exactly the row-major little-endian Float32 byte count into an owned array and rejects misaligned bytes and non-finite values with row/column context.
- A standalone loader fetches and validates a manifest before requesting its heightfield, resolves the asset relative to the manifest, rejects off-origin or escaping paths, checks HTTP/network errors, verifies bytes with Web Crypto SHA-256, then decodes. It is not called by the M0 viewer.
- A deterministic generator writes a fictional 3 × 3, 2 m-spacing fixture and its manifest under `public/worlds/synthetic-heightfield/`. It contains no geographic coordinates, real-world measurements, buildings, or roads.
- `docs/asset-contract.md` documents the accepted fields, path policy, extent tolerance, sample cap, decoder semantics, and fixture provenance.

Fixture samples in row-major order are `[-2.5, 0, 1.25, 10, 11.5, 12, 20, 21, 22.75]`. The generated binary is 36 bytes with SHA-256 `4e5e18b484af53448acdee1bffed54035c3bef7607381c3249ce255f2e2ceb14`.
