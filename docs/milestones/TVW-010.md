# TVW-010 handback: optional browser building layer

**Status:** Fix round 3 implementation is complete and submitted for independent Sol re-review; this handback is not marked passed.
**Date:** 2026-10-18

## Result

Added an opt-in browser layer that loads the locally published, validated TVW-009 OSM building package over the Environment Agency terrain. The synthetic world remains the default, `/?world=m0` remains available, and `/?world=torquay-poc-001` still opens terrain without requesting buildings. The explicit route is `/?world=torquay-poc-001&buildings=1`; the terrain HUD also offers **Load OSM buildings**.

The browser verifies the building manifest, payload and package-local QA integrity, feature geometry/height provenance, and identity against the already loaded terrain before allocating meshes. It makes same-origin local requests only. Failed or invalid building data leaves terrain usable and provides retry, terrain-only, and synthetic recovery actions. The `publish-buildings` command revalidates the source package and atomically publishes byte-identical `manifest.json`, `buildings.json`, and `qa.json` into the ignored Vite public directory.

Roofs use owned Three.js triangulation with hole support. Exterior and courtyard wall edges are subdivided at terrain-grid and terrain-triangle boundaries before sampling their bases. Each feature uses one level roof at the highest sampled terrain under its complete footprint, excluding hole interiors, plus its validated tagged or estimated height. This is a visual placement convention, not a measured roof or foundation elevation; wall bases sit 0.02 m below sampled terrain to avoid seams. Invalid geometry or an unavailable terrain sample rejects the optional layer with feature context.

The visible building status reports actual feature/component and height-method counts, the validated OSM extract timestamp, OSM and Geofabrik credit, ODbL attribution, and that heights are estimates or tagged-but-unverified. Mapped counts do not establish completeness. The AOI remains `selected_pending_coverage` / `not_checked`; road and remaining feature checks are outstanding, and M2 remains incomplete.

## TVW-010 fix round 1

The independent review findings were addressed with focused checks and regressions:

- The publisher rejects source and terrain paths that are equal or ancestor/descendant paths before staging. Tests cover a source nested below the terrain output and a terrain package nested below the source, and confirm every input file is preserved.
- Building rings are normalized to a stable winding and start point; holes, components, and component order are canonicalized. Validation rejects crossing or nested holes, overlapping component interiors, and coordinates outside the local AOI. It continues to accept point-contact components and islands contained by a hole.
- The browser requires QA package identity fields to match the validated manifest and payload identity. Fully rehashed loader tests mutate world ID, payload byte length, and SHA-256.
- QA mean-height comparison allows the documented three-decimal Python summary rounding.
- Package downloads are bounded while reading the response stream, even with absent or understated `Content-Length`, and cancel once the cap is exceeded. Oversized declared lengths are rejected before body consumption.
- The UI displays the validated `extractTimestamp` as the extract vintage and keeps the complete height-method breakdown visible after hiding and showing the layer.

## TVW-010 fix round 2

Polygon component overlap detection now partitions each ring edge at its intersections with the other polygon's exterior and hole boundaries. It tests a point from each resulting boundary interval against the other polygon's strict interior, in both directions. This detects boundary-contained overlap such as a diamond whose vertices touch the square boundary while its edges lie inside the square. Point and shared-edge contacts remain allowed when interiors are disjoint, and an island fully contained inside another component's hole remains valid.

A new fully rehashed `loadBuildingPackage` regression uses the square/diamond package with `footprintAreaM2=24`; its payload and QA identities are regenerated so validation reaches topology checks. Another rehashed loader control accepts adjacent squares sharing only an edge. Existing schema controls continue to accept isolated point contact and an island inside a hole.

## TVW-010 fix round 3

Overlap validation now finds a strict interior witness for each valid polygon using scanlines between its vertex elevations, then checks whether that witness lies in the other polygon's strict interior. This closes coincident-boundary cases where all component edges are shared and boundary-interval tests alone have no interior point to inspect. Boundary comparisons still use geometry, not serialized ring-string equality.

Two fully rehashed loader regressions reject a feature whose two components are the same 2 m square: one has identical rings and the other adds a collinear midpoint to one ring. Both use a summed declared area of 8 m² and refreshed payload/QA/package identities. The prior rehashed square/diamond overlap case still rejects. Controls continue to load isolated point contacts and adjacent squares sharing an edge without interior overlap; schema validation continues to allow an island inside a hole.
